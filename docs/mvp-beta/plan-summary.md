# MVP 데모 기획 요약

> 2026-08-18 현재 기준. 2026-08-13~14의 정적 베타 계획, 기존 계약 우선, 1~4장·WebP·6MB, 주문 전 수동 검토 차단과 별도 완료 주문 시나리오는 **superseded/historical**이다. 4탭 및 `/orders` redirect 해석도 최신 3탭·신청 목록 흐름으로 대체되었다. 당시 근거는 [decision-log.md](./decision-log.md)의 D-001~D-012에 보존한다.

## 문서 목적과 기준

현재 데모 구현 우선순위는 다음과 같다.

1. 사용자의 2026-08-17 최종 원칙
2. [`../MVP_DEMO_CANONICAL.md`](../MVP_DEMO_CANONICAL.md)
3. 최종 유저플로우의 화면·분기 순서
4. 최종 와이어프레임의 화면 필드·CTA·콘텐츠 구조
5. 최종 PRD·기능명세의 업무 의미와 데이터 요구
6. OpenAPI·Mock·DB·기존 구현

API·DB는 최종 흐름을 기계적으로 표현해야 하며, 기존 계약과 충돌한다는 이유로 고객 흐름을 축소하지 않는다. 계약 영향은 별도 검토하되 OpenAPI·Mock·DB·앱·문서를 같은 변경 단위에서 정합화한다.

## 사용자 결과

MCM 제품을 보유한 고객이 모바일 우선 웹에서 제품을 실제 촬영하고, 사진 기반 AI 예상 분석, 추천 디자인·목업, Mock 주문·결제, 수거 후 공식 장인 실물 검수, 변경 조건 승인, 제작·배송, 디지털 ESG 보증서까지 하나의 일관된 데모 흐름을 경험한다.

## 핵심 유저플로우

1. 서비스 소개를 보고 로그인하거나 게스트로 홈의 실제 hero 영상과 `상품 진단하기` CTA를 확인한다.
2. 정면·후면·상단·하단·좌측면·우측면 6면과 일련번호 사진을 실제 카메라 또는 파일 폴백으로 모두 등록한다.
3. 카테고리, 구매 연도, 사용 기간, 희망 용도를 입력한다. 시리얼과 상태 메모는 선택이다.
4. 접수·AI 분석 중·보완 요청·완료 상태를 확인한다.
5. 상태·손상·오염, 예상 재활용 가능률 72%, 정품 사전 적합도 예상 91%와 제작 제약을 확인한다.
6. 추천 후보를 비교하고 RE:BORN 여권지갑 목업을 확인한다.
7. 수거 정보를 입력하고 최초 예상 제작비 180,000원으로 Mock 결제를 완료한다.
8. `ORDER_PLACED` 뒤 제품을 수거하고 공식 장인 최종 실물 검수를 진행한다.
9. `CHANGE_REQUIRED`의 변경 사유와 68%, 195,000원, 4~5주 조건을 고객이 승인한다.
10. 하단 `신청 내역`의 `/orders` 목록에서 상품을 선택해 `/orders/demo` 상세를 열고 제작 준비→장인 제작→품질 최종 검수→배송→수령 완료를 조회한다.
11. 완료 건의 ESG 보증서와 Passport 데모 정보를 확인한다.
12. PC `/operations`에서 같은 신청의 단계별 관리자·장인 담당과 다음 단계 진행을 확인한다.

예외 분기는 다음처럼 고정한다.

- 보완 요청: 사진·정보를 보존하고 재제출 후 접수 현황으로 복귀한다.
- 품질 미달: 성공 분석을 만들지 않고 해당 사진 재촬영을 안내한다.
- AI 비대상: 공식 가품 판정이 아니라 사전 접수 불가로 안내한다.
- 추천 0건: 신청으로 강제 진행하지 않고 안내·재등록 경로를 제공한다.
- 실물 검수 변경 없음: `PRODUCTION_READY`로 바로 진행한다.
- 변경 조건 거절·제작 불가: `CANCELED`와 Mock 결제 취소·환불 안내로 종료한다.

## 포함 기능

- 모바일 실제 카메라와 파일 선택 폴백
- 정면·후면·상단·하단·좌측면·우측면·일련번호 사진 7장, JPG/JPEG·PNG, 장당 10MB 검증
- 카메라 왕복 동안 사진·제품 정보 유지
- 접수·분석·보완·완료·품질 미달·AI 비대상 상태
- 중앙 Fixture/seed 기반 AI 예상치와 일관된 사용자 카피
- 추천 비교와 정적/데모 목업 인터랙션
- 수거 정보, Mock 결제, 주문 완료
- 주문 후 공식 장인 실물 검수와 변경 조건 승인·거절
- 제작·품질·배송·수령 타임라인
- 완료 후 디지털 ESG 보증서·Passport 데모
- PC 운영 콘솔의 목록·상세·다음 단계 Fixture 진행
- 로딩, 빈 데이터, 오류, 권한 거부, 폴백 상태

## 실제 연동 제외

- 실제 OpenAI 판단만으로 정품·제작 가능 여부를 결정하는 기능
- 실시간 생성형 3D와 생산용 모델
- 실제 결제사·택배사·정품 인증·탄소 검증 기관
- 실제 장인 계정·검수 입력·생산 배정과 live 운영 데이터 연동
- 실제 환불, A/S, 고객센터, 법적 효력 보증서
- NFC 하드웨어 발급과 네이티브 iOS/Android 앱

제외 항목은 Fixture와 정적 자산으로 시연할 수 있지만 실제 서비스처럼 과장하지 않는다.

## 데이터 구조 요점

- `DemoCase`: 모든 고정 제품·식별자·예상값·변경값·최종값의 SSOT
- `Product` / `ProductPhoto`: 카테고리, 구매 연도, 사용 기간, 희망 용도, 선택 시리얼·상태 메모, 7개 사진 역할
- `Submission`: `SUB-RB-20260817-0001`, 분석 상태, 보완 요청, 분석 모드
- `AnalysisResult`: 사진 기반 예상 상태·손상·오염·72%·91%, 제약과 고지
- `DesignCandidate`: RE:BORN 여권지갑과 비교 후보, 예상 수치·기간·비용, 목업 자산
- `Order` / `Pickup`: `RB-20260817-0001`, 최초 조건, 수거 정보, Mock 결제와 상태
- `Inspection`: 주문 후 실물 검수 결과, 변경 사유, 68%·195,000원·4~5주
- `ChangeDecision`: 고객 승인·거절과 시각, 멱등성 정보
- `ProgressEvent` / `Shipment`: 제작·품질·배송 단계와 다음 행동
- `Certificate`: `ESG-RB-20260817-0001`, 68%, 예상 3.43kg CO2e, 데모 Passport 정보

예상 분석값과 실물 검수값은 서로 다른 필드로 보존한다. 변경값으로 최초 예상값을 덮어쓰지 않는다.

## 정합화 결정 요약

- 사용자 최종 원칙과 Canonical 문서가 이전 API 계약 v1.1.0/UI 우선 결정보다 상위다.
- 1~4장·JPEG/PNG/WebP·6MB와 이후 4장 규칙은 필수 구도 7장·JPG/PNG·10MB로 대체한다.
- 주문 전 수동 검토·운영자 승인은 골든 경로에서 제거한다.
- 전문가 판단은 Mock 주문·결제와 수거 뒤 실물 검수에서만 수행한다.
- 조건 변경 승인·거절은 정적 진입점이 아니라 현재 데모 상태 흐름이다.
- 별도 완료 신청과 프레젠테이션 ID를 만들지 않고 한 주문의 변경 이력을 끝까지 사용한다.
- 모든 사용자 카피는 사진 기반 예상과 주문 후 실물 검수 결과를 구분한다.

자세한 현재 결정은 [decision-log.md](./decision-log.md)의 D-013~D-022, 과거 결정은 D-001~D-012에서 확인한다.
