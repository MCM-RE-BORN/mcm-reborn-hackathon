# MVP 베타 기획 요약

## 문서 목적과 기준

이 문서는 2026-08-13 최신 MVP 산출물을 베타 UI 구현 기준으로 정규화한다. 우선순위는 개발 지시서에 따라 다음과 같다.

1. `MCM RE_BORN MVP_PRD_2026-08-13.md`
2. `MCM RE_BORN MVP_유저플로우_2026-08-13.md`
3. `MCM RE_BORN MVP_기능명세서_2026-08-13.xlsx`
4. `와이어프레임.html`
5. Figma `beta` 섹션
6. 저장소의 기존 계약·문서·코드

샘플 제품명, 날짜, 금액, 수치와 화면 메모는 요구사항이 아니라 데모 콘텐츠로 취급한다. API·DB 계약은 별도 승인이 없으므로 이 UI 작업에서 변경하지 않는다.

기능명세 워크북은 `기능` 단일 시트, 사용 범위 `B2:J56`의 55행이다. 기능 테이블은 29행부터 시작하며 30~56행의 27개 데이터 행에 23개 계층형 기능 ID가 있다. 모든 기능 상태는 `작성중`이고, 상위 요구 2~5만 중요도 `높음`, 나머지는 `중간`이다. 1.1.1, 1.1.2, 2.1.1, 2.1.2만 상세 수용 기준·예외가 채워져 있고 후반 세부 기능의 설명값 `2`는 미완성 placeholder로 판단해 요구사항으로 확장하지 않는다.

## 사용자 결과

MCM 제품을 보유한 고객이 모바일 우선 반응형 웹에서 서비스 가치를 이해하고, 제품 등록부터 AI 사전 분석, 추천 디자인 및 3D 목업 확인, 신청·가상 결제, 제작 진행 조회, 디지털 ESG 보증서까지 하나의 데모 흐름을 경험한다.

## 핵심 유저플로우

1. 서비스 소개를 보고 로그인하거나 게스트로 홈을 둘러본다.
2. 로그인·회원가입 UI를 거쳐 고객 홈으로 이동한다.
3. 제품 정면·측면·내부·시리얼 사진과 제품 정보를 등록한다.
4. 접수·분석 중·보완 요청·완료 상태를 확인한다.
5. 분석 가능 건은 상태 등급, 재활용률, 활용 부위와 제작 제약을 확인한다.
6. 분석 결과 기반 후보를 비교하고 한 디자인의 3D 목업 진입점을 확인한다.
7. 수거·주문자 정보를 입력하고 가상 결제 후 신청을 완료한다.
8. 접수→검수→제작→품질확인→배송→완료 진행 단계를 조회한다.
9. 완료 건의 디지털 ESG 보증서와 MCM Passport 정보를 확인한다.

예외 분기는 다음처럼 고정한다.

- 보완 요청: 재제출 후 접수 현황으로 복귀한다.
- 품질 미달: 성공 분석을 만들지 않고 해당 사진 재촬영을 안내한다.
- 정품 수동 검토 신호: 정품·가품 판정으로 표현하지 않고 신청 진입을 차단한다.
- 추천 0건: 신청으로 강제 진행하지 않고 안내·재등록 경로를 제공한다.
- 실물 검수 조건 변경: 계약이 없는 베타 UI 진입점만 제공하고 실제 승인·거절 처리는 하지 않는다.

## 베타 포함 기능

- 서비스 소개, 대상 제품과 AI 예상치/실물 차이 고지
- 데모 로그인·회원가입 UI와 게스트 탐색
- 제품 사진 1~4개 업로드 UI, 정면·측면·내부·시리얼 슬롯
- 접수·분석·보완·완료·품질 미달·수동 검토 안내 상태
- 분석 결과의 상태 등급·재활용률·소재·손상·활용 부위
- 추천 카탈로그 비교와 제품 상세/3D 목업 진입점
- 주문자·수거 정보 입력, 가상 결제, 신청 완료
- 제작·배송 진행 타임라인
- 디지털 ESG 보증서·Passport 상세와 공유 진입점
- 로딩, 빈 데이터, 재시도 오류, 권한 안내를 위한 공용 상태 컴포넌트
- 모바일·데스크톱 반응형 레이아웃

## 데이터 구조 요점

- `User`: 고객 식별자, 이름, 이메일, 전화번호, 약관 동의
- `Product` / `ProductPhoto`: 소유자, 제품 유형, 시리얼, 상태 메모, 사진 역할과 파일 메타
- `Submission`: 제품, 접수 상태, 보완 요청, 품질·정품 검토 신호
- `AnalysisResult`: 등급, 소재·손상, 예상 재활용률·면적, 활용/제외 부위, 제작 제약
- `DesignCandidate`: 제품명, 설명, 이미지/3D 자산, 필요 면적, 예상 기간·비용
- `Application` / `Pickup`: 선택 디자인, 배송·수거 정보, 동의, 신청 상태
- `Payment`: 데모 수단·금액·상태
- `ProgressEvent` / `Shipment`: 제작·배송 단계, 시각, 다음 행동
- `Certificate`: 보증서 번호, 발급일, 제품, 재활용률, 데모 ESG 수치, Passport 진입 정보

식별자는 `submissionId`, `applicationId`, `certificateId`로 분리한다. 베타 코드는 기존 API 계약의 명칭과 열거값을 우선하고 계약에 없는 최신 기획 필드는 정적 표시 데이터로만 둔다.

## 정합화 결정 요약

- 기존 `openapi.yaml`, `mock-data.json`, `supabase-schema.sql`은 승인된 계약 `1.1.0`이므로 변경하지 않는다.
- 최신 기획의 고객용 베타는 기존 계약 위의 정적 UI 프레젠테이션 레이어로 구현한다.
- 기존 계약의 업로드 제한(1~4개, JPEG/PNG/WebP, 장당 6MB)을 실제 UI 검증값으로 사용한다.
- `REVIEW_REQUIRED`는 정품 판정이 아니라 수동 검토 신호이며 신청을 생성하지 않는다.
- 기존 카탈로그 3종(파우치, 카드 지갑, 키링)을 데이터 기준으로 유지하고, Figma의 여권 지갑은 시각 데모 후보로만 표시한다.
- 실물 검수 조건 재승인, 회원가입 연동, NFC, 실제 결제는 계약 밖이므로 진입점만 구현한다.
- 자세한 근거와 검토한 대안은 [decision-log.md](./decision-log.md)에 기록한다.
