# 데모 MVP PRD

> 2026-08-17 현재 기준. 이전의 “1~4장·6MB·WebP, 주문 전 수동 검토 차단, 운영자 선승인” 범위는 **superseded/historical**이다. 제품·시나리오 값은 [`MVP_DEMO_CANONICAL.md`](./MVP_DEMO_CANONICAL.md)를 따른다.

이 문서는 최종 PRD와 유저플로우를 반영한 제품 완료 기준이다. 2026-08-19 구현은 실제 브라우저 카메라와 v2 API 기반 고객·운영 여정, OpenAPI 25개 API operation을 구현하는 23개 v2 Route Handler 파일·Supabase 계약을 제공한다. 분석 결과는 서버 `DEMO_FIXTURE` 모드에서 재현 가능하게 생성할 수 있으며 신청·마이페이지·보증서·운영 데이터는 API 응답을 사용한다. 실제 CUSTOMER/OPERATOR 전체 원격 여정과 OpenAI LIVE·결제사·물류사 연동은 staging 검증 대상으로 구분한다.

## 제품 정의

사용자가 MCM 가방을 모바일로 촬영하거나 사진을 올리면 사진 기반 AI 예상 분석을 확인하고, 추천 디자인·목업·Mock 주문·수거 후 공식 장인 실물 검수·변경 조건 승인·제작·ESG 보증서까지 하나의 웹 데모로 체험하게 한다.

## 목표

- 실제 촬영부터 AI 예상 분석까지 자연스러운 제품 접수 경험을 보여 준다.
- AI가 어려운 수치는 중앙 Fixture 또는 재현 가능한 예상치로 안정적으로 시연한다.
- 추천 제품의 이미지, 예상 가격·기간·재활용률과 목업을 비교할 수 있게 한다.
- AI 판단으로 Mock 주문·결제를 완료한 뒤 수거된 실물을 장인이 마지막으로 점검하는 순서를 명확히 한다.
- 실물 검수의 변경 조건을 고객이 승인한 뒤 제작·배송·보증서까지 짧은 데모 안에서 재현한다.
- 외부 서비스 실패에도 Fixture로 골든 패스를 끝낼 수 있게 한다.

## 사용자

- 고객 `CUSTOMER`: 자신의 촬영·분석·주문·변경 승인·진행·보증서만 조회·진행한다.
- 운영자 `OPERATOR`: 데모 주문과 상태를 조회하며 PC 통합 운영 콘솔에서 단계별 관리자·장인 담당을 확인한다. 주문 전 장인 승인 게이트를 수행하지 않는다.
- 장인은 별도 인증 역할이 아니라 `OPERATOR` 경계 안의 단계별 담당 표시다. 실제 장인 계정·배정은 포함하지 않는다.

## 포함 범위

| 기능 | MVP 완료 조건 |
|---|---|
| 데모 인증 | 고객·운영자 계정으로 역할에 맞는 화면과 API에 접근한다. |
| 이미지 접수 | 정면·후면·상단·하단·좌측면·우측면 6면과 일련번호 슬롯에 JPG/JPEG·PNG 사진을 각각 1장씩, 총 7장 등록한다. 장당 최대 10MB이며 모바일 후면 카메라와 파일 폴백을 제공한다. |
| 제품 정보 | 제품 카테고리, 구매 연도, 사용 기간, 희망 용도를 받고 카메라 왕복 뒤에도 유지한다. 시리얼과 상태 메모는 선택이다. |
| 이미지 품질 게이트 | 분석 기준에 못 미치는 사진에는 `422 IMAGE_QUALITY_INSUFFICIENT`, `RECAPTURE_REQUIRED`, 이미지별 한국어 안내를 반환하고 성공 분석을 만들지 않는다. |
| AI 예상 분석 | 상태·손상·오염·예상 재활용률과 정품 사전 적합도 예상치를 중앙 시나리오로 반환한다. 72%와 91%는 예상이며 정품·제작 가능 확정이 아니다. |
| 추천·목업 | 분석 결과에 맞는 후보를 비교하고 `RE:BORN 여권지갑`의 정적 다각도 목업 또는 3D 데모 인터랙션을 제공한다. |
| 홈·공통 탐색 | 홈의 실제 hero 영상과 `상품 진단하기` CTA를 제공한다. 해당 CTA와 `나의 RE:BORN 인증서 보기`는 같은 공통 ActionButton을 사용한다. 하단 내비게이션은 `신청 내역`·`홈`·`마이페이지` 3개다. |
| 신청·Mock 결제 | AI 사전 적합 신호가 주문 가능인 골든 경로에서 180,000원, 수거 무료 조건으로 주문 `RB-20260817-0001`을 만든다. |
| 신청 내역 | `/orders`에서 완료된 AI 분석 결과와 주문 신청 상품을 함께 보여 준다. 분석 결과는 동일 분석 상세로, 신청 상품은 `/orders/demo` 상세로 이동하며 주문 상세에는 진행·배송 점 사이 연결선을 포함한 타임라인을 표시한다. |
| 최소 운영 콘솔 | PC `/operations`에서 신청 목록을 확인하고 상세를 선택해 현재 관리자·장인 담당 단계의 다음 허용 상태로 한 번씩 진행한다. 현재는 Fixture이며 실제 주문을 변경한다고 표현하지 않는다. |
| 주문 후 실물 검수 | 제품 수거 후 `EXPERT_INSPECTION`을 수행한다. 골든 경로는 `CHANGE_REQUIRED`이며 68%, 195,000원, 4~5주 변경안을 제시한다. |
| 고객 변경 승인 | 변경 사유·전후 조건을 확인하고 승인하면 제작, 거절하거나 제작 불가이면 취소·Mock 환불로 진행한다. |
| 진행·배송 | 제작 준비·제작·품질 최종 검수·배송·수령 상태와 Mock 배송 정보를 고객에게 보여 준다. |
| ESG 보증서 | `COMPLETED` 뒤 `ESG-RB-20260817-0001`, 최종 재활용률 68%, 예상 탄소 절감 3.43kg CO2e를 표시한다. |
| 이벤트 | 인증 사용자만 핵심 퍼널 이벤트를 전송한다. 이벤트·metadata allowlist, 리소스 가시성 검사와 rate limit을 적용하고 실제 개인정보를 넣지 않는다. |

상세 필드, 상태 코드와 열거값은 `openapi.yaml`을 따른다.

## 비기능 요구

- 고객은 자신의 리소스만, 운영자는 역할에 허용된 리소스만 읽는다.
- OpenAI와 Supabase 비밀값은 서버에서만 사용한다.
- 동일 생성·승인 요청의 재시도를 고려해 계약에 정의된 멱등성 키를 사용한다.
- 정상·오류·빈 상태·권한 거부·보완 요청·변경 승인과 외부 제공자 실패를 검증한다.
- 사진 품질 오류는 AI 제공자 장애가 아니므로 hybrid Fixture 성공으로 바꾸지 않는다.
- AI 정품 사전 적합도는 주문 참고 신호로만 표시하며 정품 또는 가품 확정 문구를 쓰지 않는다.
- 주문 전에는 제작 가능·재활용 범위·견적을 확정 표현으로 표시하지 않는다.
- 접수·주문·보증서 화면은 중앙 시나리오의 식별자·제품·수치와 변경 이력을 공유한다.
- 데모 값과 Mock 기능을 실제 가격, 물류, 탄소 검증이나 법적 보증으로 표현하지 않는다.

## MVP 완료 기준

- 실제 모바일 카메라 또는 파일 폴백에서 정면·후면·상단·하단·좌측면·우측면·일련번호 사진 7장을 모두 등록할 수 있다.
- PC 운영 콘솔에서 신청 목록→상세→단계별 담당 확인→허용된 다음 단계 진행을 시연할 수 있다.
- 고객 골든 흐름과 대표 예외 흐름을 재현할 수 있다.
- Mock 주문 뒤 수거·실물 검수·변경 조건 승인·완료·보증서를 한 주문으로 확인할 수 있다.
- AI 예상 72%에서 검수 후 68%로 변경된 이력과 가격·기간 변경이 같은 주문에 연결된다.
- 루트에서 `python validate_package.py`가 통과한다.
- 앱 변경은 저장소 루트에서 `npm --prefix mcm-reborn ci`, `npm --prefix mcm-reborn run lint`, `npm --prefix mcm-reborn run typecheck`, `npm --prefix mcm-reborn run build`가 통과한다.
- 현재 `mcm-reborn/package.json`에는 테스트 스크립트가 없다. 자동 테스트를 실행했다고 표시하지 말고, 추가 전까지 완료 조건별 수동·계약 검증을 기록한다.
- 새 환경에서 루트 `.env.example`을 `mcm-reborn/.env.local`로 복사해 구성할 수 있다.
- `docs/DEMO.md`의 로컬 Fixture 복구 경로로 외부 API 없이도 시연을 완료한다. v2 API를 실제 staging에 연결하면 같은 시나리오로 Auth/RLS/Storage/RPC와 OpenAI LIVE 제공자 실패 폴백을 별도 검증한다.
- 사람 리뷰와 스테이징 확인을 거치고 Canonical 문서·OpenAPI·Mock·DB·앱이 일치한다.
